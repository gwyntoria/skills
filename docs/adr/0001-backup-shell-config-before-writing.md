# 写入 shell 配置前先备份，安装前原件与每次改动分开保存

`setup-ubuntu.sh` 会改写 `~/.bashrc`、`~/.zshrc`、`~/.config/fish/config.fish`。它保留合并语义：用户自有内容留在原处，脚本只更新自己管理的 `setup-ubuntu.sh` 托管块，并兼容读取旧 `env-setup-wsl.sh` 标记，因此"把配置改写成只有托管内容"会毁掉用户的 alias、`ZSH_THEME` 和第三方 `source`。为了任何一次改动后都能回滚，写入前在同一目录留下两份备份：`<配置名>.pre-env-setup-wsl.bak` 是首次写入前（文件尚未被本脚本托管时）建立的安装前原件，只此一份、永不覆盖；`<配置名>.env-setup-wsl.bak-<UTC 时间戳>` 是每次改动各一份的上一版。备份失败即放弃覆盖，原文件保持不动。

## Considered Options

- **只留上一版（改动前的实现）**：第二次改动之后，安装前的配置就永久消失，只能回滚一级。
- **只留安装前原件**：能回到安装之前，但回不到"上一次改动前"；排查单个组件的问题时只能整份重来。
- **重写成只含托管内容的干净文件**：配置更整洁，但用户自己的内容只剩在备份里，改坏一次等于丢配置。

## Consequences

- 备份与被备份的 rc 同目录：`~/.bashrc` 的备份因此是隐藏文件，`config.fish` 的不是。
- 命名沿用 `setup-agents.sh` 的 `.pre-<事件>.bak-<UTC 时间戳>` 约定，但备份只增不删，脚本不提供清理入口，恢复靠运行时打印的 `cp -p` 命令。
- 已经运行过旧版本的用户，配置里已有托管块，无法再补建安装前原件；脚本会明确提示，而不是拿当前文件伪造一份"原件"。

托管标记统一使用入口文件名 `setup-ubuntu.sh`。旧 `env-setup-wsl.sh` 标记在暂存副本中校验并转换，仅替换完整标记行，保留组件内容和用户正文；同名块跨新旧名称重复、标记交叉或未闭合时停止该配置写入。迁移随正常配置更新进行，未选择的其他 shell 不因标记改名而额外写入；nvm 清理兼容两种名称，实际需要更新时才统一标记。

备份文件继续使用原有命名，已有备份不移动。安装前原件检查同时识别新旧外层标记，避免把已配置的文件误存为安装前原件；恢复命令仍指向改写前的完整备份。迁移后的配置不保证能由旧脚本继续管理，如需退回旧脚本，先恢复其打印的改写前备份。
